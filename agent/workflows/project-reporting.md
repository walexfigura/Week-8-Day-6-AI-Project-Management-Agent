# Workflow: Project reporting

The `report` command builds the briefing deterministically from persisted state. When you summarize in an investigation:

1. **Executive summary:** classification, whether the primary milestone is projected to slip or only lost slack, the main bottleneck.
2. **Key facts with sources:** task IDs, message IDs, timestamps.
3. **Latest updates:** what changed since the last check, and who said it.
4. **Pending decisions:** approvals waiting and questions only the project lead can answer.
5. **Recommended next steps:** ordered, concrete, each tied to a person or approval ID.
6. **Labels:** "verified", "owner estimate", "unverified claim", "assumption".

Keep it short enough to read in two minutes.
